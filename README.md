# BELUGA RU — обновлённый сайт

В архиве находятся:
- `index.html` — обновлённый сайт с адаптивным дизайном, поиском по правилам и ролям, событиями, FAQ и расширенной админ-панелью.
- `worker.js` — серверная часть админки для Cloudflare Workers. Пароль администратора и ключ JSONBin хранятся на сервере, а не в HTML.

## Что добавлено

- Новый адаптивный интерфейс в стиле BELUGA RU.
- Разделы «Главная», «Правила», «Роли», «События» и «FAQ».
- Поиск по правилам, ролям и частым вопросам.
- Добавление, редактирование и удаление ролей, правил, событий и FAQ из админки.
- Настройка цветов, описания, приглашения Discord и объявления на главной.
- Онлайн берётся из Discord Widget API. Случайные числа больше не подставляются.
- Количество участников можно указать вручную; сайт не выдаёт случайное число за реальную статистику.
- Резервное копирование и восстановление настроек в JSON.
- Пароль администратора проверяется сервером. После смены он хранится в KV в виде PBKDF2-хеша.

## Важно: сначала защити старые ключи

В предыдущем HTML был встроен мастер-ключ JSONBin. Он больше не используется в новой версии. Поскольку старый ключ находился в клиентском коде, его нужно **заменить в JSONBin** и использовать новый только в Cloudflare Worker.

1. Открой JSONBin и перевыпусти (rotate/regenerate) Master Key. Если сервис не позволяет заменить ключ, создай новый ключ/бин и используй новые значения.
2. Не вставляй новый ключ в `index.html`, GitHub Pages или другие публичные файлы.

## Подключение облачной админки

Новая страница сайта может открываться и без Worker, но в таком режиме админ-панель не даст войти и изменения не будут синхронизироваться между посетителями. Для общей админки нужно один раз развернуть серверный модуль.

### 1. Создай Cloudflare Worker

1. Войди в Cloudflare и открой **Workers & Pages**.
2. Создай Worker с именем, например, `beluga-ru-admin-api`.
3. Замени стартовый код содержимым файла `worker.js` и нажми Deploy.
4. Скопируй адрес Worker, например `https://beluga-ru-admin-api.ТВОЙ-АККАУНТ.workers.dev`.

### 2. Создай KV namespace

В Cloudflare открой **Workers & Pages → KV → Create namespace** и назови его `AUTH_KV`.
Затем в настройках Worker добавь этот namespace как binding с переменной **AUTH_KV**.

KV нужен для безопасного хранения нового пароля в виде хеша после его изменения из админ-панели.

### 3. Добавь переменные и секреты Worker

В настройках Worker открой **Settings → Variables and Secrets** и задай:

**Secrets:**
- `ADMIN_PASSWORD` — начальный пароль администратора. Используй длинный пароль минимум из 12 символов. Не используй старый `beluga2024`.
- `SESSION_SECRET` — длинная случайная строка не короче 32 символов.
- `JSONBIN_MASTER_KEY` — новый Master Key JSONBin после перевыпуска.

**Variables:**
- `JSONBIN_BIN_ID` — ID JSONBin bin, в котором хранятся настройки сайта.
- `ALLOWED_ORIGIN` — адрес сайта, например `https://beluga.example`. На время локальной проверки можно поставить `*`, но для опубликованного сайта лучше указать точный адрес сайта.

После добавления переменных повторно разверни Worker.

### 4. Подключи Worker к сайту

В `index.html` найди строку:

```js
const API_BASE = '';
```

Вставь адрес Worker между кавычками, например:

```js
const API_BASE = 'https://beluga-ru-admin-api.ТВОЙ-АККАУНТ.workers.dev';
```

Сохрани `index.html` и загрузи его на хостинг сайта. Адрес `ALLOWED_ORIGIN` в Cloudflare должен совпадать с адресом сайта (включая `https://`, без завершающего `/`).

### 5. Проверка

Открой в браузере адрес:

`https://ТВОЙ-WORKER.workers.dev/api/health`

Должен появиться ответ с `"ok": true`.

Затем открой сайт, нажми **F3** или ⚙, введи начальный пароль, который задан в `ADMIN_PASSWORD`, и проверь сохранение темы/настроек.
После входа можно сменить пароль на вкладке **«БЕЗОПАСНОСТЬ»**. Новый пароль будет храниться в KV в виде PBKDF2-хеша.

## Если пока не хочешь настраивать Cloudflare

Открой `index.html` локально или загрузи его на статический хостинг. Публичные страницы будут работать, а онлайн-индикатор попробует получить данные Discord Widget. Админка и общая синхронизация начнут работать только после подключения Worker.

## Что важно знать

- Для настоящей общей админки серверная часть обязательна: один HTML-файл не может безопасно скрыть пароль и мастер-ключ от посетителей.
- Если Discord Widget отключён в настройках сервера, онлайн будет отображаться как `—`. Это намеренно: сайт не показывает выдуманный онлайн.
- Количество участников задаётся вручную в админке, потому что стандартный публичный Discord Widget не предоставляет достоверное общее количество участников сервера.
